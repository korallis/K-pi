# Spec first

Research repository behavior and conventions before proposing requirements, design and tasks. Requirements name observable acceptance criteria, constraints and non-goals; design identifies existing extension points and risks; tasks are ordered feature slices with explicit checks and ownership. Publish through the node's supplied response/artifact channel. Read-only specifier roles do not write repository documents; without a durable channel, return a proposal and say it is not published.

Do not implement production code. Do not invent evidence or mark narrative criteria executable.
