## The seven issues and the required behaviour

1. **Claude Code version rejection.** OAuth requests sent `user-agent: claude-cli/2.1.75`; Anthropic now refuses below 2.1.251 (`claude_code_version_too_old`). Ship upstream's one-line bump (cherry-pick 96317e50b from the `upstream` remote, record it in UPSTREAM.md §6), pin the floor in packages/ai/test/anthropic-auth-token.test.ts, and make K-π explain a recurrence once (sent version, required version, `npm install -g @korallis/k-pi@latest`) without cooling the slot or failing over.
2. **`invalid_grant` refresh warning with a stack trace every turn.** K-π kept a copy of the official OAuth grant in accounts.secrets.json and refreshed it independently of the base runtime, which also refreshes auth.json on every request; Anthropic rotates refresh tokens so one copy always dies. Rule: a pool's official slot is `official: true`, credential-free, served from auth.json, refreshed only by the runtime; other slots stay K-π-refreshed. `reconcileOfficialCredentials` at session_start binds by content. `invalid_grant` marks the slot `needsLogin` (unselectable, shown in the widget) and says so once with the exact `/accounts login <pool> <slot>`; transient refresh failures cool with a plain reason. Never a stack trace in a notification. This amends PRD AC-10.2 and spec §13 (record NEEDS_HUMAN gate NH-05 as CLOSED, decided by the owner: "fix /login anthropic so K-π synchronizes refreshed OAuth credentials into account routing and supports two distinct subscription slots").
3. **Board boxes show nothing and nothing is interactive.** Engine appends `node.started {run, model?}` / `node.finished {run, status, elapsed_ms, cost_usd?, result?, session?, error?}` to events.jsonl. A pure board-activity module folds events + checkpoint into per-stage activity. Compact widget: DONE cells `<elapsed> · <n> calls · $<cost> est.`, CURRENT cell last tool + target + elapsed, PENDING `—`, plus a NOW row; 1 s ticker while a job is live; re-entrant installWidget. Chat narration one "K-π " line per node start/finish, route change, failover, and gate — never per tool call. `/kpi status` is an interactive overlay (←/→ select stage, Enter detail with status/elapsed/cost/model/tool calls/last events/result file, t transcript, r refresh, q/Esc), usable mid-run. Widths 200/120/80/60 keep every field; pty graders in scripts/pty-rows keep their tokens. AGENTS cell reads `AGENTS n · k nodes · w workers` from the sessions registry.
4. **Plan approval.** Human node `plan-approval` after `plan` in coding-loop.gated.json; dialog shows a rendered stack.json summary; options Approve plan / Request changes (feedback required, appended to the plan prompt via `feedbackPath`; no cap on revisions); `submitHuman({approved, feedback?})`; approval.result records feedback; a gate without dialog UI stops NEEDS_HUMAN with recovery "approval" and the resume command. The release gate gets the same shape: Approve / Request changes (→ implement) / Stop.
5. **Sessions visibility.** Graph nodes are in-process sessions; workerRole nodes and spawn_background are separate `kpi --mode rpc` processes over bus.jsonl; no sub-agent API. One process-local registry (bus/sessions-snapshot.ts) of live node sessions and buses; `BackgroundBus.liveWorkers()`; `/agents` prints kind/id/role/model/pid/alive/elapsed/tools/last/node/job, the worker caps, the mechanism sentence, and the live job line.
6. **Onboarding.** `/onboarding` (no alias) composed from exported `loginPoolInteractively`, `promptResearchKeys`, `runKStackSetup`: welcome (what K-π is, the plan and release gates, worker processes), per-pool login or skip, Exa / Perplexity / Firecrawl keys, K-stack map; auto-runs at TUI startup only when every pool has zero slots and no model is available; "Not now" closes for this launch. Firecrawl becomes the third research service (POST `/v2/search`, Bearer, `sources:[{type:"web"}]`, never scrapeOptions, same caps and failure classes, auto order exa → perplexity → firecrawl, tool `firecrawl_search`, `/accounts login firecrawl`). Story US-31, package RP-20.
7. **Self-healing graphs, no caps (owner: "graphs should never fail", "there shouldn't be a cap at all", "if it hits a timeout it should retry").** Delete maxCostUsd, timeoutMs, maxSteps, maxNodeRuns, maxRounds, maxTransientRetries and `--max-cost-usd/--timeout-ms/--max-rounds` (refused with a plain message); graph limits are `{maxConcurrency}` only; cost and elapsed are report-only. Transient failures (408/429/5xx, timeout, transport) retry indefinitely with 1 s doubling to a 60 s ceiling, no jitter, checkpoint before every wait, a `node.retry` event and one "K-π " line per retry, a RETRY row on the board. Repeated review output or failing-AC set → re-plan with `repair.json` (two automatic re-plans per operator touch); a failed `test` round counts as a round and identical evidence fingerprints across consecutive failed test rounds are a witness too; then pause NEEDS_HUMAN offering Give guidance / Keep going / Stop. Terminal nodes become pause nodes `{type:"pause", recovery, reason, resume:[…]}`. Run vocabulary RUNNING | NEEDS_HUMAN | DONE | STOPPED; NEEDS_HUMAN and STOPPED are finished-but-resumable (`/kpi <job>` resumes anything but DONE); only RUNNING is live (PRD AC-24.3 stays); old runs on disk keep their finished status until resumed; `loop.terminal` keeps its name with a `recovery` field; every NEEDS_HUMAN reason ends with `resume with /kpi <job>`. Detach the running loop from the `/kpi` command handler (today the interactive loop awaits the handler, so nothing works during a job): the handler starts the loop, keeps a module-level live handle with an AbortController, returns at once; `/kpi stop` aborts immediately, writes `stop.json`, records STOPPED; `/kpi <goal>` while a job runs is refused; dialogs from the detached loop use the captured ctx (valid until session replacement). Package RP-21; amend PRD US-05, spec §6/§7/§8, AGENTS.md's stopping-condition row, README §8/§9.
